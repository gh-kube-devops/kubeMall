# 用户模块技术文档

## 🎯 模块概述

用户模块提供完整的用户认证、授权和用户管理功能，采用 JWT 进行身份认证，Spring Security 进行权限控制，并包含完善的日志追踪体系。

---

## 📋 一、功能列表

### 1.1 认证功能（AuthController）

| 功能 | 方法 | 路径 | 权限要求 | 说明 |
|-----|------|------|---------|------|
| 用户注册 | POST | /auth/register | 无（公开）| 创建新用户，自动分配默认角色 |
| 用户登录 | POST | /auth/login | 无（公开）| 验证用户名密码，返回 JWT Token |

### 1.2 用户管理功能（UserController）

| 功能 | 方法 | 路径 | 权限要求 | 说明 |
|-----|------|------|---------|------|
| 查询所有用户 | GET | /users | ADMIN | 获取用户列表 |
| 查询单个用户 | GET | /users/{id} | ADMIN 或本人 | 获取指定用户信息 |
| 更新用户信息 | PUT | /users/{id} | ADMIN 或本人 | 更新用户名、邮箱 |
| 修改密码 | PATCH | /users/password | 已登录 | 修改当前登录用户密码 |
| 分配角色 | POST | /users/{id}/roles | ADMIN | 为用户分配角色 |
| 删除用户 | DELETE | /users/{id} | ADMIN | 删除指定用户 |

## 🔧 二、技术特性

### 2.1 JWT 认证

**工作原理：**

用户登录 → 验证密码 → 生成 JWT Token → 返回 Token
后续请求 → 携带 Token → 解析验证 → 设置认证信息

**Token 结构：**

```json
{
    "sub": "username",
    "roles": ["ROLE_USER", "ROLE_ADMIN"],
    "iat": 1745312400000,
    "exp": 1745316000000
}
```

**核心组件：**

- JwtUtil：Token 生成、解析、验证
- JwtAuthenticationFilter：拦截请求，解析 Token 并设置认证上下文

### 2.2 权限控制

**基于方法注解：**

| 注解 | 含义 | 示例 |
|-----|------|------|
| @PreAuthorize("permitAll()") | 公开访问 | 注册、登录 |
| @PreAuthorize("isAuthenticated()") | 需要登录 | 修改密码 |
| @PreAuthorize("hasRole('ADMIN')") | 需要 ADMIN 角色 | 用户列表、删除用户 |
| @PreAuthorize("hasRole('ADMIN') or #id == authentication.principal.id") | ADMIN 或本人 | 查询单个用户、更新用户 |

**角色定义：**

| 角色 | 权限范围 |
|-----|---------|
| ROLE_ADMIN | 所有操作（用户管理、角色分配、删除用户）|
| ROLE_USER | 仅限个人操作（查看/修改自己的信息、修改密码）|

### 2.3 AOP 日志

**切面功能：**

- 自动记录 Controller 层方法调用
- 自动记录 Service 层方法调用
- 记录方法执行耗时
- 统一捕获异常并记录

**日志示例：**

```
18:00:00 [traceId] INFO  - ▶ Controller: UserController.deleteUser(..)
18:00:00 [traceId] INFO  - ▶ Service: UserServiceImpl.deleteUser(..)
18:00:01 [traceId] INFO  - ◀ Service: UserServiceImpl.deleteUser(..) cost=15ms
18:00:01 [traceId] INFO  - ◀ Controller: UserController.deleteUser(..) cost=18ms
```

### 2.4 TraceId 链路追踪

**工作原理：**

- 请求进入时生成唯一 TraceId
- 存入 MDC（Mapped Diagnostic Context）
- 同一请求的所有日志自动携带该 TraceId
- 请求结束时清理

**日志输出：**

```
18:00:00.123 [http-nio-8080-exec-1] [a1b2c3d4] INFO  - ➡ POST /auth/login
18:00:00.125 [http-nio-8080-exec-1] [a1b2c3d4] INFO  - 解析成功 - 用户名: testuser
18:00:00.130 [http-nio-8080-exec-1] [a1b2c3d4] INFO  - ⬅ POST /auth/login cost=7ms
```

**作用：**

- 搜索 TraceId 可查看完整请求链路
- 分布式系统可跨服务追踪
- 快速定位问题

### 2.5 Result 统一返回

**响应格式：**

```json
{
    "code": 200,
    "message": "success",
    "data": { ... },
    "timestamp": "2026-04-21 18:00:00"
}
```

**业务状态码：**

| code | 含义 | 场景 |
|------|------|------|
| 200 | 成功 | 正常响应 |
| 400 | 参数错误 | 请求参数校验失败 |
| 401 | 未授权 | 未登录、Token 过期 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 资源不存在 | 用户不存在 |
| 409 | 冲突 | 用户名已存在 |
| 500 | 服务器错误 | 系统内部异常 |

### 2.6 DTO 分层

**结构：**

```
dto/
├── request/
│   ├── LoginRequest.java
│   ├── RegisterRequest.java
│   ├── UserUpdateRequest.java
│   ├── ChangePasswordRequest.java
│   └── AssignRoleRequest.java
└── response/
    ├── LoginResponse.java
    └── UserResponse.java
```

**设计原则：**

| 类型 | 用途 | 特点 |
|-----|------|------|
| Request DTO | 接收客户端请求 | 包含验证注解（@Valid）|
| Response DTO | 返回给客户端 | 不含敏感信息（密码等）|
| Entity | 数据库映射 | 与表结构对应 |

**示例：**

RegisterRequest（请求）：

```json
{
    "username": "testuser",
    "password": "123456",
    "email": "test@example.com"
}
```

UserResponse（响应）：

```json
{
    "id": 1,
    "username": "testuser",
    "email": "test@example.com",
    "roles": ["ROLE_USER"],
    "createdAt": "2026-04-21T18:00:00",
    "updatedAt": "2026-04-21T18:00:00"
}
```

## 🔄 四、请求处理流程

```
请求进入
    ↓
RequestLogFilter (生成 TraceId，记录开始时间)
    ↓
JwtAuthenticationFilter (解析 Token，设置认证信息)
    ↓
Spring Security FilterChain
    ↓
AuthorizationFilter (检查 @PreAuthorize 权限)
    ↓
Controller (业务处理)
    ↓
AOP 日志 (记录方法调用)
    ↓
Response (返回响应)
    ↓
RequestLogFilter (记录结束时间，清理 MDC)
```

## 📝 五、API 测试示例

### 5.1 用户注册

```bash
curl -X POST http://localhost:8080/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"123456","email":"test@example.com"}'
```

### 5.2 用户登录

```bash
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"testuser","password":"123456"}'
```

### 5.3 查询用户列表（需要 ADMIN）

```bash
curl -X GET http://localhost:8080/api/v1/users \
  -H "Authorization: Bearer <token>"
```

### 5.4 修改密码

```bash
curl -X PATCH http://localhost:8080/api/v1/users/password \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"oldPassword":"123456","newPassword":"654321"}'
```

### 5.5 分配角色（需要 ADMIN）

```bash
curl -X POST http://localhost:8080/api/v1/users/1/roles \
  -H "Authorization: Bearer <admin_token>" \
  -H "Content-Type: application/json" \
  -d '{"roles":["ADMIN","USER"]}'
```

### 5.6 删除用户（需要 ADMIN）

```bash
curl -X DELETE http://localhost:8080/api/v1/users/1 \
  -H "Authorization: Bearer <admin_token>"
```

## 🚨 七、常见问题

| 问题 | 检查项 |
|-----|-------|
| 启动报错：连接数据库失败 | PostgreSQL 是否启动、用户名密码、端口 5432 |
| 404 错误 | 请求路径是否正确、是否添加 /api/v1 前缀 |
| 401 未授权 | 请求头是否包含 Authorization、Token 是否过期 |
| 403 权限不足 | 用户角色是否满足 @PreAuthorize 要求 |
| TraceId 没有显示 | RequestLogFilter 是否配置、pattern 是否包含 %X{traceId} |
